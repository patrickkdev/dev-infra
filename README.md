# Local Dev Infrastructure

A centralized repository for managing local development dependencies using Docker Compose. This setup provides pre-configured instances of PostgreSQL, Redis, MinIO, and RabbitMQ.

## Prerequisites

* **Docker** and **Docker Compose** installed on your host machine.

## Getting Started

1. **Clone this repository** to your local machine.
2. **Setup your environment variables:**
```bash
cp .env.example .env

```


Open the `.env` file and configure your local passwords.
3. **Spin up the infrastructure:**
```bash
docker compose up -d

```


4. **Stop the infrastructure:**
```bash
docker compose down

```



## Service Reference

| Service | Internal Port | Host Port (External) | Management UI | Default User |
| --- | --- | --- | --- | --- |
| **PostgreSQL** | `5432` | `5432` | — | `postgres` |
| **Redis** | `6379` | `6379` | — | — |
| **MinIO** | `9000` | `9001` (Console) | [http://localhost:9001](https://www.google.com/search?q=http://localhost:9001) | `minio` |
| **RabbitMQ** | `5672` | `15672` (UI) | [http://localhost:15672](https://www.google.com/search?q=http://localhost:15672) | `rabbitmq` |

*Note: Ensure you map the host ports in your `compose.yml` if your applications run natively on the host machine rather than inside the `dev_net` Docker network.*

## Data Persistence

All data generated by these services is persisted locally inside the `./data/` directory. This directory is automatically ignored by Git to prevent committing local state or databases to the repository.

## Useful Commands

* **Check service status:**
```bash
docker compose ps

```


* **View real-time logs:**
```bash
docker compose logs -f

```


* **Restart a specific service (e.g., RabbitMQ):**
```bash
docker compose restart rabbitmq
